# Operating the stack

The **stack** is a docker compose deployment: Loki, Grafana, Tempo, Mimir and an OpenTelemetry collector, with a
provisioned "Claude Code usage" dashboard. It lives in `docker-compose.yml` and `stack/`.

## Run it

```sh
docker compose up -d
open http://localhost:3030        # Grafana, opens on the usage dashboard (anonymous viewer; admin/admin to log in)
```

| Service | Port | Override |
|---|---|---|
| Grafana | 3030 | `GRAFANA_PORT`, `GRAFANA_ADMIN_USER`, `GRAFANA_ADMIN_PASSWORD`, `GRAFANA_ANONYMOUS=false` |
| Loki push/query | 3100 | `LOKI_PORT` (then also change `CLAUDE_ANALYTICS_LOKI_URL` for the plugin) |
| OTLP gRPC / HTTP | 4317 / 4318 | `OTLP_GRPC_PORT`, `OTLP_HTTP_PORT` |

Tempo and Mimir are not published; Grafana and the collector reach them inside the compose network.

## Serving a team

By default, all ports are published on **127.0.0.1 only**. To make the stack reachable from other machines or
containers, set `BIND_ADDRESS=0.0.0.0`. Before you do:

- set a real admin password with `GRAFANA_ADMIN_PASSWORD`;
- set `GRAFANA_ANONYMOUS=false`, since anonymous viewers are on by default;
- put Loki behind auth. It has none of its own. The plugin's flusher can send a bearer token, basic auth and a
  tenant header (see [Install](./install.mdx#configuration));
- keep the OTLP ports (4317/4318) on loopback or behind auth too. The collector has no auth and writes whatever it
  receives into Loki, Mimir and Tempo, so an open OTLP port gets around any auth in front of Loki.

## On Grafana Cloud

For a team, send events to the company's Grafana Cloud stack instead of exposing this one
([ADR 0007](./architecture-decisions/0007-shared-stack-on-grafana-cloud.mdx)). An org admin does this once:

1. In the Grafana Cloud portal, open the stack's **Loki** details. Note the URL (`https://logs-prod-NNN.grafana.net`)
   and the numeric user ID.
2. Create an access policy with only the `logs:write` scope, and a token for it. This is the token every machine
   gets. It can add events but not read them.
3. Under the stack's Loki settings, add a stream retention rule of 90 days (`2160h`) for
   `{service_name="claude-code-usage"}`. The default is 30 days.
4. In the stack's Grafana, go to **Dashboards → New → Import** and upload
   `stack/grafana/dashboards/claude-code-usage.json`. Pick the stack's logs data source in the **Loki** variable.
5. Decide who may read the data. Anyone who can query the logs data source can see each person's usage (see
   [Install](./install.mdx#configuration) about the identity tag).

Each machine then needs these three variables, through managed settings or `~/.claude/settings.json` (never a
repository's `.claude/settings.json`):

```json
{
  "env": {
    "CLAUDE_ANALYTICS_LOKI_URL": "https://logs-prod-NNN.grafana.net",
    "CLAUDE_ANALYTICS_LOKI_BASIC_AUTH": "<user id>:<logs:write token>"
  }
}
```

The URL may also be the full push URL (`.../loki/api/v1/push`). To check a machine, run any slash command in
Claude Code, then query `{service_name="claude-code-usage"}` in the stack's Explore. If nothing arrives, a
`401`/`403` in the plugin's log means the user ID or token is wrong (see
[Troubleshooting](./how-it-works.mdx#troubleshooting)).

## Retention

| Store | Keeps | Set in |
|---|---|---|
| Loki (usage events) | 90 days; rejects samples older than 7 days | `stack/loki.yaml` |
| Tempo (traces) | 7 days | `stack/tempo.yaml` |
| Mimir (metrics) | unlimited | `stack/mimir.yaml` |

The plugin skips events older than 6 days, so a backlog that finally reaches Loki is never rejected as too old.
If you lower Loki's `reject_old_samples_max_age`, lower `maxAgeMs` in
`plugins/usage-analytics/scripts/event-buffer.mjs` with it; it is a code constant, not a setting.

## The dashboard

The "Claude Code usage" dashboard is provisioned from `stack/grafana/dashboards/`. Edit the JSON there: the
provisioned dashboard cannot be saved from the Grafana UI. [What is recorded](./what-is-recorded.mdx) describes the
labels and log lines to query.

## Native Claude Code telemetry (optional)

The collector also accepts Claude Code's built-in OpenTelemetry export (token and cost metrics, tool events) into
the same Loki, Mimir and Tempo. Delta metrics are converted to cumulative for Mimir.

```sh
CLAUDE_CODE_ENABLE_TELEMETRY=1 OTEL_METRICS_EXPORTER=otlp OTEL_LOGS_EXPORTER=otlp \
OTEL_EXPORTER_OTLP_PROTOCOL=grpc OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317 claude
```

This runs alongside the plugin; it does not replace it. See
[ADR 0001](./architecture-decisions/0001-hooks-and-local-buffer-over-native-telemetry.mdx) for why.

## Checking that events arrive

- Loki answers `http://localhost:3100/ready` once it is up.
- An end-to-end check pipes a hook payload through the real hook into a real Loki:

  ```sh
  SMOKE_LOKI_URL=http://localhost:3100 node --test test/smoke.test.mjs
  ```

- If events do not show up, the plugin's log explains why. See
  [Troubleshooting](./how-it-works.mdx#troubleshooting).
